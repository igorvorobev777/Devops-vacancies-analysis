# Анализ вакансий DevOps с RustFS и DuckDB

Учебный проект по обработке набора IT-вакансий направления DevOps. Данные хранятся в локальном объектном хранилище RustFS, а частоты навыков, пар и троек считаются двумя независимыми способами: собственной потоковой MapReduce-реализацией и SQL-запросом в DuckDB.

В проект также входят проверка совпадения результатов, анализ медианных зарплат внутри одинаковых групп опыта, региональное сравнение Москвы, Санкт-Петербурга и Новосибирска, а также сравнение производительности RustFS-конфигураций на 4, 6 и 8 дисках.

## Содержание проекта

| Файл или каталог | Назначение |
|---|---|
| `compose.yaml` | Запуск RustFS через Docker Compose; для замеров конфигурация переключается на 4, 6 или 8 дисков. |
| `stage3.py` | Подсчёт навыков и их сочетаний через MapReduce и DuckDB. |
| `stage4.py` | Сравнение результатов двух способов подсчёта. |
| `stage5.py` | Анализ медианной зарплаты для пар и троек навыков внутри одной и той же группы опыта. |
| `stage6.py` | Анализ зарплат и востребованных навыков по трём регионам. |
| `profile_stage3.py` | Три замера времени и пика памяти для одного запуска `stage3.py`; аргумент задаёт метку конфигурации дисков. |
| `upload_results.py` | Загрузка подготовленных CSV-результатов в бакет RustFS. |
| `files/devops_vacancies.csv` | Исходный CSV-файл вакансий. |
| `results/` | Локальные результаты расчётов и профилирования. |

## Использованные технологии

- Docker Desktop и Docker Compose;
- RustFS с S3-совместимым API;
- Python 3.10 или новее;
- `boto3` для доступа к объектному хранилищу;
- `duckdb` для SQL-анализа;
- `psutil` для замера памяти в скрипте профилирования.

Установка Python-зависимостей:

```powershell
py -m pip install boto3 duckdb psutil
```

## Запуск RustFS и подготовка данных

Команды ниже выполняются в PowerShell из каталога проекта:

```powershell
cd D:\rustfs
docker compose up -d
docker ps --filter "name=rustfs"
```

Локальные адреса сервиса:

- S3 API: `http://localhost:9000`;
- веб-консоль: `http://localhost:9001`.

В веб-консоли должен существовать бакет `hh-lake`, а в нём объект `devops_vacancies.csv`. Перед запуском расчётов проверьте наличие объекта в активной конфигурации хранения. Вакансии содержат поле `key_skills`; отдельные навыки в нём разделены точкой с запятой, например: `Linux; Nginx; elk; ansible; Kubernetes`.

Скрипты Python получают S3-учётные данные из переменных окружения. В текущем окне PowerShell задайте значения, совпадающие с настройками RustFS в `compose.yaml`:

```powershell
$env:RUSTFS_ACCESS_KEY = "<значение ключа доступа>"
$env:RUSTFS_SECRET_KEY = "<значение секретного ключа>"
```

## Этапы обработки

### Этап 3 — частоты навыков

```powershell
py .\stage3.py
```

MapReduce получает объект из S3 и читает CSV частями по 2 000 строк. Для каждой вакансии список `key_skills` разбивается по `;`, навыки приводятся к нижнему регистру, повторы внутри одной вакансии удаляются. Затем считаются частоты отдельных навыков, всех пар и всех троек навыков.

DuckDB выполняет SQL-запрос к тому же объекту `s3://hh-lake/devops_vacancies.csv` через расширение `httpfs`. Оба набора результатов сохраняются в `results/` как `mapreduce_counts.csv` и `duckdb_counts.csv`.

На использованном наборе оба способа сформировали по **165 879 комбинаций**.

### Этап 4 — проверка результатов

```powershell
py .\stage4.py
```

Скрипт сравнивает комбинации и их частоты, полученные MapReduce и DuckDB. Проверка завершилась сообщением о полном совпадении **165 879 комбинаций**.

### Этап 5 — зарплата и навыки

```powershell
py .\stage5.py
```

Пары и тройки сравниваются только внутри одинаковых категорий опыта, чтобы не смешивать вакансии разных грейдов. Для каждой группы опыта рассчитывается медианная зарплата по вакансиям, где встречается соответствующая комбинация. В итоговый анализ включаются комбинации, для которых выполнен заданный в программе минимальный порог частоты — **10 вакансий**. По выводу программы обработано **598 строк с парами** и **1 792 строки с тройками**.

### Этап 6 — региональный анализ

```powershell
py .\stage6.py
```

Создаются три CSV-файла:

- `stage6_region_summary.csv` — число вакансий, число вакансий с указанной зарплатой и медианная зарплата по региону;
- `stage6_salary_by_experience.csv` — те же показатели отдельно по категориям опыта;
- `stage6_top_skills.csv` — наиболее часто встречающиеся навыки по регионам.

`demand_percent` — процент вакансий региона, в которых указан навык: число таких вакансий делится на общее число вакансий региона. Поскольку вакансии без указанной зарплаты также могут содержать навыки, частота навыка и число вакансий с зарплатой для него приведены отдельно.

Итоговая сводка по загруженному набору:

| Регион | Вакансии | Вакансии с зарплатой | Медианная зарплата, ₽ |
|---|---:|---:|---:|
| Москва | 3 007 | 523 | 250 000 |
| Санкт-Петербург | 686 | 147 | 215 000 |
| Новосибирск | 160 | 45 | 165 000 |

Linux оказался самым часто указанным навыком во всех трёх регионах. В Москве далее следуют Kubernetes и Docker; в Санкт-Петербурге и Новосибирске — Docker и Kubernetes. Региональные медианы рассчитаны только по вакансиям с зарплатой, поэтому размер выборки с зарплатой меньше общего числа вакансий. Особенно осторожно следует трактовать результаты Новосибирска из-за небольшого числа объявлений.

## Сравнение конфигураций хранения

`profile_stage3.py` запускает `stage3.py` три раза и записывает длительность каждого успешного запуска и пиковую память Python. Скрипт сам **не переключает** Docker Compose: перед запуском нужно вручную включить нужную конфигурацию в `compose.yaml`.

Для каждой конфигурации используются отдельные каталоги данных RustFS на диске D. После переключения конфигурации перезапустите сервис и убедитесь, что в активном хранилище снова доступны бакет `hh-lake` и объект `devops_vacancies.csv`. Новые каталоги дисков могут содержать пустое хранилище; если бакета или объекта нет, создайте бакет и загрузите исходный CSV до замера.

Для каждой конфигурации выполните отдельно:

1. Укажите в `compose.yaml` нужное число каталогов дисков и соответствующие каталоги на диске D.
2. Перезапустите RustFS командами `docker compose down` и `docker compose up -d`.
3. Проверьте, что в этой конфигурации есть `hh-lake/devops_vacancies.csv`; при необходимости создайте бакет и загрузите CSV.
4. Запустите профилирование с тем же числом дисков, что указано в Compose:

```powershell
# Выполнять только после включения конфигурации на 4 диска и проверки объекта
py .\profile_stage3.py 4

# После переключения Compose на 6 дисков и проверки объекта
py .\profile_stage3.py 6

# После переключения Compose на 8 дисков и проверки объекта
py .\profile_stage3.py 8
```

Каждая команда `profile_stage3.py` выполняет три попытки.

| Дисков | Время, попытки (с) | Медиана времени (с) | Пик памяти Python, попытки (МБ) | Медиана памяти (МБ) |
|---:|---|---:|---|---:|
| 4 | 4,601 / 3,921 / 4,056 | 4,056 | 178,05 / 197,34 / 180,64 | 180,64 |
| 6 | 10,006 / 6,076 / 5,707 | 6,076 | 193,72 / 194,15 / 192,48 | 193,72 |
| 8 | 7,757 / 6,007 / 5,840 | 6,007 | 191,21 / 179,49 / 175,55 | 179,49 |

В этих запусках конфигурация на 4 дисках показала наименьшую медиану времени, а на 8 дисках — наименьшую медиану измеренной памяти. Замер памяти относится к процессу Python и отслеживаемым профилировщиком дочерним процессам; это не замер потребления памяти контейнера RustFS.

## Результаты и объектное хранилище

Локальные файлы результатов подсчёта для трёх конфигураций размещаются так:

```text
results/
├── 4-disks/
│   ├── mapreduce_counts.csv
│   └── duckdb_counts.csv
├── 6-disks/
│   ├── mapreduce_counts.csv
│   └── duckdb_counts.csv
└── 8-disks/
    ├── mapreduce_counts.csv
    └── duckdb_counts.csv
```

После выполнения профилирования файл замеров сохраняется как `results/stage3_profile.csv`. Скрипт `upload_results.py` предназначен для загрузки подготовленных результатов подсчёта в бакет по таким ключам:

```text
s3://hh-lake/results/4-disks/mapreduce_counts.csv
s3://hh-lake/results/4-disks/duckdb_counts.csv
s3://hh-lake/results/6-disks/mapreduce_counts.csv
s3://hh-lake/results/6-disks/duckdb_counts.csv
s3://hh-lake/results/8-disks/mapreduce_counts.csv
s3://hh-lake/results/8-disks/duckdb_counts.csv
```

Результаты сохраняются в CSV с разделителем `;` и кодировкой UTF-8.

## Порядок полного запуска

1. Запустить RustFS и проверить доступность бакета `hh-lake` и объекта `devops_vacancies.csv`.
2. Установить зависимости и задать переменные окружения с учётными данными S3.
3. Выполнить `stage3.py`, затем `stage4.py`.
4. Выполнить `stage5.py` и `stage6.py`.
5. Для каждой конфигурации на 4, 6 и 8 дисках переключить Compose, проверить наличие исходного объекта и выполнить `profile_stage3.py <число_дисков>`.
6. Добавить в GitHub исходные программы и итоговый отчёт. Не добавлять секретные ключи и случайные неуспешные замеры.
